Problem Definition & Test Strategy

Problem Definition

Modern e-commerce platform checkouts involve multi-layered, asynchronous workflows. State transformations in cart badge totals and filter overlays are highly vulnerable to regressions. Traditional testing methodologies suffer from asynchronous race conditions, lacks API-level stability checks, and offers zero pipeline feedback hooks.

Scope & Target

Unified validation of both UI and API layers in synchronization: 7 UI modules covering the complete customer journey, 1 BDD filtering framework, and 9 REST API integration test endpoints executed in parallel under headless GitHub Actions.

Testing Gaps Resolved

  • Headless Dropdowns: Resolved hover exclusions in Headless Chrome using JS fallback executors.
  • API Unpredictability: Shielded against mock instability using URL Session retries and backoff limits.
Testing Hypothesis Framework
Null ($H_0$): BDD-POM patterns and retry hooks fail to yield <5% flakiness and 100% execution pass rate.
Alternate ($H_a$): Explicit synchronization and HTTP adapters maintain 100% stability, proving headless and API resilient strategy works.

Selenium WebDriver & Dynamic Synchronization

Explicit Wait Wrapper Strategy

By implementing WebDriverWait wrapping conditions, we eliminated 100% of hardcoded sleeps (time.sleep) during locator checks. Elements are polled dynamically with a 10s maximum timeout limit. 

def click(self, locator):
    self.wait.until(
        EC.element_to_be_clickable(locator)
    ).click()

Responsive Windows Scaling & Context

In headed mode, window maximizes cleanly. For headless CI/CD operations, conftest loads --window-size=1920,1080 explicitly to prevent layout elements collapsing and throwing click anomalies.

Headless Fallback: Javascript Exec Clicks

ActionChains hover clicks fail under headless environments because layout viewports do not render visual dropdown trigger bounds. To prevent ElementNotInteractableException, we implemented js_click() inside our BasePage: 

def js_click(self, locator):
    # presence_of_element ignores visibility filters
    element = self.wait.until(
        EC.presence_of_element_located(locator)
    )
    self.driver.execute_script(
        "arguments[0].click();", element
    )

Bypasses overlay layers and clicks direct DOM references.

Reusable Step Definitions

API Robustness & Retry Strategies

urllib3 Connection Retry Strategy

The mock server endpoint (DummyJSON) is hosted behind Cloudflare WAF, causing intermittent drops and 520 server failures. To prevent test suite crashes, we configured a urllib3 Retry adapter directly onto the Session pipeline. 

retry_strategy = Retry(
    total=3,
    backoff_factor=1, # Exponential wait 1s, 2s, 4s
    status_forcelist=[500, 502, 503, 504, 520],
    allowed_methods=["GET", "POST", "PUT", "DELETE"]
)
adapter = HTTPAdapter(max_retries=retry_strategy)
self.session.mount("https://", adapter)

10-Second Hard Timeout Guard

Default requests actions block indefinitely if a connection is established but server response delays. Enforcing a global timeout=10 constraint prevents CI workflow hangs.

Schema Validations & Assertions

All REST responses undergo strict schema conformity tests, validation checks on HTTP response status codes, and latency checks guaranteeing response times below 1.5 seconds.

Test Execution, Reporting & Failure Hooks

conftest.py failure hook screenshot code 
@pytest.hookimpl(tryfirst=True, hookwrapper=True)
def pytest_runtest_makereport(item, call):
    outcome = yield
    rep = outcome.get_result()

    if rep.when == "call" and rep.failed:
        if "driver" in item.fixturenames:
            web_driver = item.funcargs.get("driver")
            if web_driver:
                path = f"screenshots/{item.name}.png"
                web_driver.save_screenshot(path)
                try:
                    import allure
                    allure.attach.file(
                        path,
                        name="failure-screenshot",
                        attachment_type=allure.attachment_type.PNG
                    )
                except ImportError:
                    pass

Pytest hook intercepts test failures at run time. Captures browser canvas layout, dumps PNG to screenshots/ folder, and attaches it straight to the Allure run logs.

Interactive Q&A Session

Technical Questions & Answers

How does the framework handle dynamic AJAX content?
It uses explicit WebDriverWait wrappers in BasePage. Actions like clicking or entering text are wrapped in checks such as EC.element_to_be_clickable or EC.visibility_of_element_located. For cart AJAX increments, a custom lambda monitors the badge count value.
Why did we choose Pytest-BDD over Robot Framework?
Pytest-BDD integrates natively with Pytest's powerful fixture subsystem, allows reusing standard python helper classes, and doesn't require learning custom syntax, while maintaining Gherkin transparency for business groups.
How does the API client retry logic work?
We mount a urllib3 Retry adapter to requests Session instance, configured to retry up to 3 times on transient error states (500, 502, 503, 504, 520) using exponential backoff scaling (wait intervals: 1s, 2s, 4s).
How are failure screenshots captured during CI runs?
A custom Pytest hook in conftest.py monitors run status. On failure, it retrieves driver instance from fixture arguments, snaps a PNG screenshot to the local filesystem, and embeds it directly into the Allure report files.
What strategy is used for test data management?
Test credentials and configurations are centralized in config/config.py. The API layer uses dynamic JSON payloads constructed at runtime via factory methods in api/payloads/ to avoid static test data pollution.
